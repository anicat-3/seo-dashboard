# SEO-дашборд

Веб-приложение для еженедельного мониторинга вебмастеров и аналитик SEO-проектов.
Ежедневно собирает данные из внешних систем по API, копит историю в PostgreSQL
и показывает дашборд по каждому проекту за любой период со сравнением
и подсветкой резких изменений.

| Системы | Что собирается |
|---|---|
| Google Analytics 4, Яндекс.Метрика | пользователи (все и органика), длительность, отказы, избранные цели |
| Google Search Console, Яндекс.Вебмастер, Bing Webmaster | клики, показы, CTR, позиция, карты сайта; страниц в поиске и ошибки диагностики (Вебмастер); ошибки обхода (Bing) |
| Topvisor, SE Ranking | позиции по запросам, средняя позиция, видимость, распределение по топам |
| PageSpeed Insights, CrUX | оценка производительности, Core Web Vitals |

> **Статус: этап 2.** Реальные коннекторы готовы для всех 9 систем: Search Console, GA4,
> Яндекс.Метрика, Яндекс.Вебмастер, Bing, Topvisor, SE Ranking, PageSpeed Insights, CrUX. Как подключить ключи —
> [docs/api-keys.md](docs/api-keys.md).

## Возможности интерфейса

- Дашборд проекта по адресу `/projects/<домен-с-дефисами>`: переключатель проектов
  с поиском, закреплённая шапка (после прокрутки сжимается до одной строки) с периодом,
  базой сравнения (в том числе свой период), группировкой графиков и якорями блоков.
- Избранные проекты: у каждого сотрудника свои, показываются первыми в сводке
  и в переключателе.
- Сводный график поисковых консолей (GSC, Вебмастер, Bing): клики и показы по умолчанию,
  CTR и позиция включаются переключателями; у каждой метрики своя шкала.
- Календарь периода с отметками: дни съёма позиций и дни с обнаруженными ошибками.
- Клик по названию серии в легенде оставляет на графике только её.
- Отчёт в PDF через печать браузера, светлая и тёмная темы, сворачиваемая боковая панель.
- Шрифты Montserrat (текст) и Oswald (заголовки) подключены локально.

## Стек

- **Backend:** Python 3.12, FastAPI, SQLAlchemy 2, Alembic, APScheduler, PostgreSQL 17.
- **Frontend:** React 18, TypeScript, Vite, TanStack Query, ECharts.
- Без Docker: PostgreSQL и приложение ставятся напрямую и одинаково работают
  на localhost и на сервере.

## Быстрый старт (Windows)

Требуется: PostgreSQL 17, Python 3.12, Node.js 20+.

```powershell
# Первичная установка: БД, .env, миграции, учётные записи, сборка фронтенда.
# Спросит пароль суперпользователя postgres и пароли учётных записей admin и seo.
.\scripts\setup.ps1

# Запуск
.\scripts\run.ps1              # http://localhost:8000
```

Учётные записи: `admin` (администратор) и `seo` (общая запись SEO-команды).
Сотрудники SEO-команды входят в два шага: логин и пароль, затем выбирают себя из списка
команды — без этого войти нельзя. Список ведёт администратор в разделе «Команда».
Администратор входит по логину и паролю, имя не выбирает.

> **Первый запуск:** пока список команды пуст, учётная запись `seo` войти не сможет.
> Добавьте сотрудников в разделе «Команда».

| Раздел | Специалист | Администратор |
|---|---|---|
| Сводка, сигналы, дашборды, позиции, пометки | ✓ | ✓ |
| Настройки проекта (подключение систем, цели, URL для PSI, перезапуск сбора) | ✓ | ✓ |
| Создание, архивирование и удаление проектов | — | ✓ |
| Подключения (доступы к API), правила подсветки, ошибки сбора | — | ✓ |
| Команда, учётные записи, журнал действий, журнал изменений | — | ✓ |

### Режим разработки

```powershell
.\scripts\run.ps1 -Dev                 # backend с автоперезапуском, порт 8000
cd frontend; npm run dev               # frontend с hot reload, http://localhost:5173
```

```powershell
cd backend
.\.venv\Scripts\python -m pytest       # тесты
.\.venv\Scripts\ruff check app         # линтер (docstring-и в стиле Google)
cd ..\frontend; npm run typecheck      # проверка типов
```

## Команды CLI

Выполняются из папки `backend`: `.\.venv\Scripts\python -m app.cli <команда>`.

| Команда | Назначение |
|---|---|
| `init-env` | создать `.env` со случайными `SECRET_KEY` и `ENCRYPTION_KEY` |
| `setup` | загрузить справочники, создать учётные записи `admin` и `seo` |
| `set-password <login>` | сменить пароль (завершает активные сессии записи) |
| `sync [--integration ID --date-from … --date-to …]` | запустить сбор немедленно |
| `detect-signals` | пересчитать подсветку изменений |
| `purge-data [--with-logs]` | удалить все проекты, доступы и собранные данные (учётные записи и команда сохраняются) |

Миграции: `.\.venv\Scripts\python -m alembic upgrade head`.
Документация API (Swagger): `http://localhost:8000/api/docs`.

## Важно

- Файл `.env` содержит секреты и не попадает в репозиторий. `ENCRYPTION_KEY`
  нужно хранить в резервной копии: без него сохранённые доступы не расшифровать.
- Снимки состояния (карты сайта, страниц в индексе, ошибки, PSI) задним числом
  не восстанавливаются. Пока приложение работает на localhost и компьютер выключен,
  в истории снимков будут пробелы.
- Приложение запускается в **одном процессе** (без `--workers`): планировщик сбора
  работает внутри него.
