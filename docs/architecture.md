# Архитектура: принятые решения

Исходные требования — документ «SEO-дашборд: источники данных, структура БД
и use-case» (28.09.2026). Здесь зафиксировано, как они реализованы и где схема
расширена относительно документа.

## Поток данных

```
 Планировщик (APScheduler, 04:00)          Пользователь
        │                                       │
        ▼                                       ▼
 services/collector ──► connectors/*      api/routes/*  ◄── React SPA
        │   CollectResult                       │
        ▼                                       ▼
 services/writer (upsert) ──► PostgreSQL ◄── services/dashboard, aggregation
        │
        ▼
 services/signals (правила → сигналы)
```

- **Коннектор не знает о БД.** Он получает расшифрованный секрет и параметры
  подключения и возвращает `CollectResult`. Запись делает `services/writer`.
  Новая система = новый модуль в `connectors/` + строка в реестре и каталоге,
  без изменения схемы БД.
- **Интерфейс коннектора** (`connectors/base.py`): `list_resources()`, `list_goals()`,
  `test()`, `collect(date_from, date_to)`, `backfill()`, `fetch_period_totals()`.
- **Сбор идемпотентен:** upsert по естественному ключу; каждый запуск перезабирает
  последние 5 дней (`REWRITE_WINDOW_DAYS`).

## Правила расчёта итогов за период

| `aggregation` | Расчёт | Примеры |
|---|---|---|
| `sum` | сумма дневных значений | клики, показы, цели |
| `weighted_avg` | среднее, взвешенное по `weight_metric_code` | CTR и позиция — по показам (как в GSC) |
| `last` | последнее значение в периоде | страниц в поиске, позиции на дату съёма |
| `period_only` | готовый итог из `period_metrics` | пользователи, отказы, длительность |

Итоги `period_only` для стандартных периодов готовятся ночью; для произвольного
периода запрашиваются у API один раз при открытии дашборда и сохраняются.

## Расширения схемы относительно документа

| Таблица | Добавлено | Зачем |
|---|---|---|
| `credentials` | `status_message`, `created_by_name` | текст ошибки для экрана UC-14 |
| `integrations` | `status`, `last_error`, `external_name`, `disabled_at` | статус «ошибка» из UC-03 6a; различие «пауза» / «отключено» (UC-05) |
| `sync_runs` | `status = 'running'`, `started_by_name` | незавершённые запуски; кто запустил вручную |
| `signals` | `kind`, `metric_code`, `segment`, `issue_id`, `period_from/to`, `change_pct`, `message`, `seen_by_name`, `resolved_at` | сигналы о новых ошибках; «открытый» сигнал не дублируется (UC-13 2a) |
| `feedback` (новая) | обращения команды, статус, ответ администратора | журнал предложений и замечаний по работе дашборда |
| `systems` | `sort_order` | порядок блоков |
| `projects`, `annotations` | `created_at` | сортировка, журнал |
| `projects` | `slug` (уникальный) | адрес проекта в URL: домен с дефисами вместо точек |
| `audit_log` | `project_name` | название проекта на момент действия; сохраняется после удаления проекта |

Коды метрик имеют префикс системы (`gsc.clicks`, `ga4.users`), поэтому
`metric_catalog.code` уникален без составного ключа.

`keyword_positions` секционирована по месяцам; секции создаёт SQL-функция
`ensure_keyword_positions_partition(date)` перед вставкой.

## Адреса проектов

Страница проекта открывается по адресу `/projects/<slug>`, где slug строится из домена:
точки и прочие знаки заменяются дефисом (`auto-parts.kz` → `/projects/auto-parts-kz`).
При совпадении добавляется суффикс `-2`, `-3`; при смене домена адрес меняется вместе с ним.
API принимает в пути и slug, и числовой ID проекта (`services/projects.py::find_project`).

## Группировка графиков

Графики строятся по дням, неделям или месяцам (`?granularity=day|week|month`):

- по дням — только для периодов до 62 дней; по неделям — от 14 дней; по месяцам — от 60 дней;
- внутри интервала действует правило агрегации метрики (сумма, взвешенное среднее,
  последнее значение);
- для пользователей в интервале показывается **сумма дневных значений** — так удобнее
  сравнивать недели и месяцы. Повторные визиты одного человека в разные дни при этом
  считаются отдельно, поэтому сумма по неделям больше точного итога в карточке,
  который по-прежнему берётся из `period_metrics`;
- распределение по топам — последний съём интервала.

## Удаление проекта

`DELETE /api/projects/{ref}` безвозвратно удаляет проект, его подключения и всю историю
(`services/projects.py::delete_project`). Доступы и журнал изменений сохраняются.
В интерфейсе действие подтверждается вводом домена проекта.

## Отчёт в PDF

Кнопка «Скачать PDF» переводит дашборд в режим печати (светлая тема, ширина листа A4,
без панели и элементов управления) и открывает диалог печати браузера — в нём выбирается
«Сохранить как PDF». Серверной генерации PDF нет: так отчёт всегда совпадает с тем,
что настроено на экране (период, сравнение, группировка, выбранные серии).

## Подсветка изменений

- Правило: метрика + сегмент + база сравнения (`wow` — 7 дней к предыдущим 7,
  `mom` — 30 к 30) + порог. Правило проекта переопределяет общее.
- Сегмент `*` — «каждый сегмент метрики» (поисковик и регион позиций).
- Сигнал открыт, пока `resolved_at IS NULL`. Повторная проверка обновляет значение;
  когда ухудшение пропадает, сигнал закрывается. Отметка «просмотрено» не закрывает
  сигнал и не порождает новый.
- Новая ошибка диагностики Вебмастера всегда создаёт сигнал.

## Безопасность

- Пароли — Argon2id. Сессия — подписанная cookie (`HttpOnly`, `SameSite=Lax`);
  в ней хранится отметка `password_changed_at`, поэтому смена пароля завершает
  все сессии учётной записи (UC-16).
- Секреты доступов — Fernet, ключ в `ENCRYPTION_KEY`. В API секрет не возвращается,
  в журнал изменений и логи не пишется.
- CSRF: изменяющие запросы требуют заголовок `X-Requested-With`; CORS выключен.
- Роли: специалист работает с дашбордами и настройками проектов; администратору
  дополнительно доступны создание, архивирование и удаление проектов, подключения
  к API, правила подсветки, ошибки сбора, команда, учётные записи и оба журнала.
  Права проверяются на сервере (зависимость `Admin`), интерфейс лишь скрывает разделы.

## Сравнение и избранное

- База сравнения: предыдущий период, предыдущий месяц, год назад или **свой период**
  (`compare=custom&compare_from=…&compare_to=…`). Разбор параметров —
  `api/deps.py::period_params`, результат — `services/periods.py::Comparison`.
- `favorite_projects (owner, project_id)` — избранное сотрудника. `owner` —
  `member:<id>` (сотрудник, выбранный при входе) или `account:<id>` (администратор):
  учётная запись общая, поэтому избранное закрепляется за человеком.

## Сводный график консоли

Клики, показы, CTR и средняя позиция GSC, Вебмастера и Bing выводятся на одном графике,
как в самой Search Console: у каждой метрики своя скрытая шкала (шкала позиции перевёрнута),
точные значения — во всплывающей подсказке. По умолчанию включены клики и показы.
Это осознанное исключение из правила «одна шкала на график»: задача графика — сравнить
динамику, а не абсолютные значения.

## Команда и журнал действий

- `team_members` — список сотрудников под общей учётной записью. Вход специалиста
  двухшаговый: после проверки пароля сессия «ожидает» выбора сотрудника
  (`POST /auth/member`); список команды отдаётся только после верного пароля.
  Администратор имя не выбирает — его учётная запись закреплена за одним человеком.
- Имя сотрудника берётся из списка при каждом запросе: переименование сразу видно
  в журналах, выключенный сотрудник теряет доступ без смены пароля.
- `activity_log` — входы, выходы и просмотры страниц. Интерфейс отправляет адрес
  открытой страницы (`POST /activity`), сервер определяет раздел, проект и период;
  повторный просмотр той же страницы в течение 2 минут не записывается.

## Реальные коннекторы

| Система | Модуль | Доступ |
|---|---|---|
| Search Console, GA4 | `connectors/google_apis.py` | OAuth Google (`connectors/oauth.py`) |
| Яндекс.Метрика, Вебмастер | `connectors/yandex_apis.py` | OAuth Яндекса |
| Bing Webmaster | `connectors/bing.py` | API-ключ |
| Topvisor | `connectors/topvisor.py` | User ID + API-ключ |
| SE Ranking | `connectors/seranking.py` | API-токен |
| PageSpeed Insights, CrUX | `connectors/google_speed.py` | API-ключ Google Cloud |

OAuth-токены обновляются автоматически; если коннектор обновил токен
(`Connector.secret_updated`), сборщик сохраняет новый секрет в БД.
Позиции Topvisor и SE Ranking при подключении загружаются за выбранный период
(`settings.history_days`) или только последним съёмом.

## Этап 2: как добавлялись коннекторы

Для каждой системы: класс-наследник `Connector` в `connectors/<system>.py`,
регистрация в `connectors/registry.py::REAL_CONNECTORS`, тесты на записанных
ответах API. Для Google и Яндекса дополнительно — OAuth-поток
(`/api/oauth/<provider>/start|callback`) с сохранением refresh-токена в `credentials`.
