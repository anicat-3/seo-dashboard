# Инструкция администратора SEO-дашборда

Дашборд раз в сутки собирает данные из Google, Яндекса, Bing, Topvisor, SE Ranking,
PageSpeed Insights и CrUX и показывает их по проектам. Администратор отвечает за то,
чтобы сбор работал: подключает аккаунты сервисов, заводит проекты и сотрудников,
разбирает ошибки и обращения команды.

## Роли

Учётных записей две: `admin` (администратор) и `seo` (SEO-команда, общая на всех
сотрудников). Сотрудник при входе выбирает своё имя из списка — оно попадает в журналы,
пометки и обращения. Администратор входит без выбора имени.

| Что | Администратор | SEO-команда |
|---|:---:|:---:|
| Сводка, дашборды проектов, позиции, сигналы, выгрузка PDF и CSV | ✓ | ✓ |
| Избранные проекты, пометки на графиках, «Просмотрено» у сигналов | ✓ | ✓ |
| Подключить систему к проекту, изменить цели, пауза, «Отключить» | ✓ | ✓ |
| Перезапуск сбора за период, загрузка истории | ✓ | ✓ |
| Название и домен проекта, URL для PageSpeed Insights | ✓ | ✓ |
| Отправить обращение (форма внизу страниц) | ✓ | ✓ |
| Создать, архивировать, удалить проект | ✓ | — |
| Удалить отключённую систему из проекта вместе с историей | ✓ | — |
| **Подключения**: доступы к аккаунтам Google, Яндекса, ключи API | ✓ | — |
| **Правила подсветки**: пороги изменений, свои пороги проекта | ✓ | — |
| **Команда**: список сотрудников для входа | ✓ | — |
| **Учётные записи**: смена паролей | ✓ | — |
| **Ошибки сбора**, «Запустить сбор сейчас» | ✓ | — |
| **Обращения**, **Журнал действий**, **Журнал изменений** | ✓ | — |

Разделы администратора скрыты из меню SEO-команды; прямая ссылка на них открывает сводку.

## Первый запуск

1. **Пароли.** «Учётные записи» → задайте надёжные пароли `admin` и `seo`. Пароль `seo`
   сообщите команде.
2. **Команда.** «Команда» → добавьте сотрудников (имя и фамилия). Без этого
   специалист не сможет войти: выбор имени обязателен.
3. **Подключения.** «Подключения» → добавьте доступы:
   - **Google** (Search Console, GA4) — «Войти через Google», выберите аккаунт на
     странице Google. Повторите для каждого рабочего аккаунта.
   - **Яндекс** (Метрика, Вебмастер) — «Войти через Яндекс» → откройте страницу
     входа → «Разрешить» → вставьте код подтверждения в окно дашборда (код действует
     10 минут). Для другого аккаунта сначала выйдите из текущего в браузере.
   - **Bing, Topvisor, SE Ranking, PageSpeed Insights, CrUX** — «Подключить по
     API-ключу». Один ключ Google Cloud подходит и для PSI, и для CrUX — добавьте его
     для обеих систем.

   После добавления нажмите «Проверить» — статус должен стать «Работает».
   Где взять ключи: [api-keys.md](api-keys.md).
4. **Проекты.** «Проекты» → «Новый проект» (название и домен). Затем «Настройки
   проекта» → «Подключить систему»: система → аккаунт → ресурс (сайт, счётчик,
   проект в Topvisor) → цели → «Проверить» → «Подключить». История загрузится сама
   за несколько минут.

## Ежедневная работа

- **Сбор** идёт автоматически в 4:00 (Минск). Каждый раз перезабираются последние
  5 дней — так подтягиваются запоздавшие данные Google и Яндекса.
- **Счётчики в меню.** Красная цифра у «Ошибок сбора» — что-то не собирается; у
  «Обращений» — новые сообщения команды; у «Сигналов» — резкие изменения метрик.
- **Ошибки сбора** — загляните хотя бы раз в неделю:
  - *«доступ отозван или истёк»* — в «Подключениях» нажмите «Войти заново» (Google,
    Яндекс) или «Переподключить» с новым ключом;
  - *«Нет связи с …: адрес не найден»* — сервер не видит сервис в сети: проверьте
    интернет или VPN. Для Topvisor это частая причина;
  - *«Квота API исчерпана»* — сбор повторится сам на следующий день.
  После исправления нажмите «Запустить сбор сейчас» или «Сбор и журнал» → перезапуск
  за нужный период в настройках проекта.
- **Обращения** — предложения и замечания команды. Ставьте статус: «На паузе»,
  «Отложено», «Закрыто», «Отклонено»; при необходимости оставьте комментарий.
- **Правила подсветки** — общий порог по умолчанию 10 %. Для «шумного» проекта или
  метрики задайте свой порог в настройках проекта, ненужное правило выключите.

## На что обращать внимание

- **Ключи в файле `.env` не удаляйте и не меняйте**, пока через них подключены
  аккаунты. У Google и Яндекса там несколько приложений с номерами `_1`, `_2`…:
  новые входы идут через `_1`, остальные нужны, чтобы обновлялись токены уже
  подключённых аккаунтов. Ключи в чатах и письмах не пересылайте.
- **Удаление необратимо.** Удаление проекта или отключённой системы стирает всю
  накопленную историю. Если система просто не нужна сейчас — «Пауза» или
  «Отключить»: история сохранится, систему можно вернуть.
- **Доступ нельзя удалить**, пока он используется в проектах — сначала переключите
  или отключите эти подключения.
- **Уход сотрудника.** «Команда» → «Выключить» (его сессия завершится, записи в
  журналах останутся) и смените пароль `seo` в «Учётных записях» — смена пароля
  завершает все активные сессии этой записи. Если сотрудник имел доступ к рабочим
  Google/Яндекс-аккаунтам, отзовите доступ приложения в настройках аккаунта и
  переподключите его в дашборде.
- **Кто что менял** — «Журнал изменений» (настройки, подключения, удаления);
  **кто когда заходил и что смотрел** — «Журнал действий».
- **Компьютер с дашбордом** должен быть включён в 4:00, иначе ночной сбор
  пропустится (данные догрузятся при следующем сборе, если пропуск не больше 5 дней;
  за больший период — перезапуск вручную в «Сбор и журнал»).
- **Резервные копии** базы и переезд на сервер — [deployment.md](deployment.md).
